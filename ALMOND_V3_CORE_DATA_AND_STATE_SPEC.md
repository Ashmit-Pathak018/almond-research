## 1. Relational Truth: SQLite Schema Architecture

SQLite is the single, durable source of truth. All vector stores (Chroma), timeline indexes, and entity graph caches are derived accelerators rebuildable directly from these tables.

### 1.1 `namespaces` Table
Separates tenants, users, or distinct agent memory boundaries.
```sql
CREATE TABLE IF NOT EXISTS namespaces (
    namespace_id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    description TEXT,
    created_at REAL NOT NULL,
    metadata_json TEXT DEFAULT '{}'
);
```

### 1.2 `memories` Table (The MemoryBlock Root)
```sql
CREATE TABLE IF NOT EXISTS memories (
    memory_id TEXT PRIMARY KEY,
    namespace_id TEXT NOT NULL REFERENCES namespaces(namespace_id) ON DELETE CASCADE,
    content TEXT NOT NULL,
    summary TEXT,
    tag TEXT NOT NULL,                  -- CORE_RULE, USER_PROFILE, PROJECT_FACT, TASK, EPISODIC, SMALL_TALK
    tier TEXT NOT NULL,                 -- L1_HOT_CACHE, L2_ACTIVE_RAM, L3_VIRTUAL_SWAP, L4_ARCHIVE
    state TEXT NOT NULL,                -- CREATED, ACTIVE, DECAYING, ARCHIVED, DELETED
    importance_score REAL NOT NULL,     -- Range [1.0, 10.0]
    access_count INTEGER DEFAULT 1,
    lambda_decay REAL NOT NULL,         -- Resolved from tag
    stability_factor REAL NOT NULL,     -- Scaled from access_count
    
    -- Bi-Temporal & Reference Clocks (Unix Epoch Seconds)
    event_time REAL,                    -- When the phenomenon occurred in the world
    created_at REAL NOT NULL,           -- Wall-clock creation timestamp
    updated_at REAL NOT NULL,           -- Last structural update timestamp
    last_accessed_at REAL NOT NULL,     -- Last reinforcement / retrieval hit
    expires_at REAL,                    -- Optional TTL boundary
    
    -- Provenance & Lineage
    source_type TEXT NOT NULL,          -- user, assistant, system, tool, import
    session_id TEXT,
    source_event_id TEXT,               -- If generated by a tool or message ID
    provenance_json TEXT DEFAULT '{}',  -- Additional origin metadata
    
    FOREIGN KEY (namespace_id) REFERENCES namespaces(namespace_id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_memories_namespace ON memories(namespace_id);
CREATE INDEX IF NOT EXISTS idx_memories_tier_state ON memories(tier, state);
CREATE INDEX IF NOT EXISTS idx_memories_event_time ON memories(event_time);
CREATE INDEX IF NOT EXISTS idx_memories_last_accessed ON memories(last_accessed_at);
```

### 1.3 `entities` and `entity_aliases` Tables
```sql
CREATE TABLE IF NOT EXISTS entities (
    entity_id TEXT PRIMARY KEY,
    namespace_id TEXT NOT NULL,
    canonical_name TEXT NOT NULL,
    entity_type TEXT NOT NULL,          -- PERSON, ORGANIZATION, LOCATION, PROJECT, CONCEPT, TOOL
    summary TEXT,
    created_at REAL NOT NULL,
    updated_at REAL NOT NULL,
    metadata_json TEXT DEFAULT '{}',
    FOREIGN KEY (namespace_id) REFERENCES namespaces(namespace_id) ON DELETE CASCADE,
    UNIQUE(namespace_id, canonical_name)
);

CREATE TABLE IF NOT EXISTS entity_aliases (
    alias_id TEXT PRIMARY KEY,
    entity_id TEXT NOT NULL,
    alias_name TEXT NOT NULL,
    created_at REAL NOT NULL,
    FOREIGN KEY (entity_id) REFERENCES entities(entity_id) ON DELETE CASCADE,
    UNIQUE(entity_id, alias_name)
);

CREATE TABLE IF NOT EXISTS memory_entities (
    memory_id TEXT NOT NULL,
    entity_id TEXT NOT NULL,
    mention_offset_start INTEGER,
    mention_offset_end INTEGER,
    confidence REAL NOT NULL,           -- Range [0.0, 1.0]
    PRIMARY KEY (memory_id, entity_id),
    FOREIGN KEY (memory_id) REFERENCES memories(memory_id) ON DELETE CASCADE,
    FOREIGN KEY (entity_id) REFERENCES entities(entity_id) ON DELETE CASCADE
);
```

### 1.4 `facts` Table (Extracted Assertions)
```sql
CREATE TABLE IF NOT EXISTS facts (
    fact_id TEXT PRIMARY KEY,
    namespace_id TEXT NOT NULL,
    subject TEXT NOT NULL,
    predicate TEXT NOT NULL,
    object TEXT NOT NULL,
    state TEXT NOT NULL,                -- VERIFIED, INFERRED, CONFLICTING, SUPERSEDED
    confidence REAL NOT NULL,           -- Range [0.0, 1.0]
    superseded_by TEXT REFERENCES facts(fact_id),
    valid_from REAL,                    -- Beginning of assertion validity
    valid_to REAL,                      -- End of assertion validity (if superseded)
    created_at REAL NOT NULL,
    FOREIGN KEY (namespace_id) REFERENCES namespaces(namespace_id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS memory_facts (
    memory_id TEXT NOT NULL,
    fact_id TEXT NOT NULL,
    PRIMARY KEY (memory_id, fact_id),
    FOREIGN KEY (memory_id) REFERENCES memories(memory_id) ON DELETE CASCADE,
    FOREIGN KEY (fact_id) REFERENCES facts(fact_id) ON DELETE CASCADE
);
```

### 1.5 `events` Table (Structured Chronological Timeline)
```sql
CREATE TABLE IF NOT EXISTS events (
    event_id TEXT PRIMARY KEY,
    namespace_id TEXT NOT NULL,
    title TEXT NOT NULL,
    description TEXT,
    event_type TEXT NOT NULL,           -- POINT, INTERVAL, ORDERED, UNKNOWN_TIME
    start_time REAL,                    -- Unix epoch seconds
    end_time REAL,                      -- Unix epoch seconds (for intervals)
    relative_anchor TEXT,               -- e.g., 'before event_x', 'spring 2024'
    confidence REAL NOT NULL,
    created_at REAL NOT NULL,
    FOREIGN KEY (namespace_id) REFERENCES namespaces(namespace_id) ON DELETE CASCADE
);

CREATE TABLE IF NOT EXISTS memory_events (
    memory_id TEXT NOT NULL,
    event_id TEXT NOT NULL,
    PRIMARY KEY (memory_id, event_id),
    FOREIGN KEY (memory_id) REFERENCES memories(memory_id) ON DELETE CASCADE,
    FOREIGN KEY (event_id) REFERENCES events(event_id) ON DELETE CASCADE
);
```

### 1.6 `ingestion_jobs` Table (Persistent Asynchronous Worker State)

CREATE TABLE IF NOT EXISTS ingestion_jobs (

### 1.7 `retrieval_traces` and `audit_events` Tables

## 2. First-Class `MemoryPolicy` Specification

V3 elevates memory policies into first-class objects. Policies govern the lifecycle, decay anchor, promotion, demotion, and retention rules per memory category or namespace.

```python
class DecayAnchorMode(str, Enum):
    DECAY_FROM_ACCESS = "DECAY_FROM_ACCESS"  # Default for durable facts, profiles, rules
    DECAY_FROM_EVENT  = "DECAY_FROM_EVENT"   # Default for episodic memories (real-world event date)
    DECAY_FROM_UPDATE = "DECAY_FROM_UPDATE"  # Decays from when assertion was last modified

@dataclass(frozen=True)
class MemoryPolicy:
    tag: MemoryTag
    decay_rate_lambda: float
    stability_divisor: float
    decay_anchor: DecayAnchorMode
    promotion_threshold: float     # P_eff required to promote L3 -> L2 (e.g. 5.0)
    demotion_threshold: float      # P_eff dropping below demotes L2 -> L3 (e.g. 2.5)
    archive_threshold: float       # P_eff dropping below moves L3 -> L4 (e.g. 1.0)
    deletion_threshold: float      # P_eff dropping below marks for deletion (e.g. 0.2)
    retention_period_days: Optional[float] = None
    extraction_enabled: bool = True
    conflict_resolution: str = "FLAG_CONFLICT"  # FLAG_CONFLICT or AUTO_SUPERSEDE
```

### Canonical Policy Defaults:
- **`CORE_RULE`**: $\lambda = 0.001$, `DECAY_FROM_ACCESS`, Never archived.
- **`USER_PROFILE`**: $\lambda = 0.002$, `DECAY_FROM_ACCESS`, High retention.
- **`PROJECT_FACT`**: $\lambda = 0.01$, `DECAY_FROM_ACCESS`.
- **`TASK`**: $\lambda = 0.05$, `DECAY_FROM_UPDATE`.
- **`EPISODIC`**: $\lambda = 0.08$, `DECAY_FROM_EVENT` (decays from when the event occurred in real world).
- **`SMALL_TALK`**: $\lambda = 0.20$, `DECAY_FROM_ACCESS`, Fast demotion to L4.

### 2.1 Memory Lifecycle State Machine
Governs the progression of a memory block across storage tiers and decay stages.

```
       [Creation]
           │
           ▼
       ┌────────┐
       │CREATED │
       └───┬────┘
           │ Ingested & Verified
           ▼
       ┌────────┐  P_eff > Tier Threshold
       │ ACTIVE │◄─────────────────────────────┐
       └───┬────┘                              │
           │ P_eff drops below active threshold│ Reinforcement / Access Hit
           ▼                                   │
      ┌─────────┐                              │
      │DECAYING ├──────────────────────────────┘
      └───┬─────┘
          │ Evicted from L2 -> L3 / Summarized to L4
          ▼
      ┌─────────┐
      │ARCHIVED │
      └───┬─────┘
          │ Explicit user/retention purge
          ▼
      ┌─────────┐
      │ DELETED │ ──► Trigger Cascade Deletion
      └─────────┘
```

- **`CREATED`**: Payload received and structured into `MemoryBlock`; not yet indexed in vector or graph tiers.
- **`ACTIVE`**: Paged into `L2_ACTIVE_RAM` with high freshness and immediate candidate availability.
- **`DECAYING`**: Natural exponential decay has reduced $P_{\text{eff}}$; candidate for page-out to `L3_VIRTUAL_SWAP`.
- **`ARCHIVED`**: Compacted into single-sentence summary (`L4_ARCHIVE`) or held in cold SQLite storage.
- **`DELETED`**: Soft/hard deleted; cascade cleans vector representations, entity relations, and event linkages.

### 2.2 Ingestion Job State Machine
Governs the resilient queue of the hardened `MemoryWorker`.

```
        ┌──────────┐
        │ RECEIVED │
        └────┬─────┘
             │ Enqueued to SQLite
             ▼
        ┌──────────┐
   ┌───►│  QUEUED  │
   │    └────┬─────┘
   │         │ Picked by Worker thread
   │         ▼
   │    ┌────────────┐
   │    │ PROCESSING │
   │    └────┬───────┘
   │         ├── Success ──────────────────────────► ┌─────────┐
   │         │                                       │ SUCCESS │
   │         └── Failure (attempts < max_retries)    └─────────┘
   │             ▼
   │        ┌─────────┐
   └────────┤  RETRY  │ (with exponential backoff + jitter)
            └────┬────┘
                 │ Failure (attempts >= max_retries)
                 ▼
            ┌─────────────┐
            │ DEAD_LETTER │
            └─────────────┘
```

### 2.3 Knowledge Fact State Machine
Governs truth, contradiction, and supersession of facts extracted from memories.

- **`VERIFIED`**: Directly stated by user or corroborated by primary system source.
- **`INFERRED`**: Extracted via heuristic or entity relation model; retains lower confidence prior.
- **`CONFLICTING`**: Contradicts an existing verified/inferred fact; flagged for developer/agent arbitration.
- **`SUPERSEDED`**: Replaced by a more recent assertion (e.g., "I moved from Seattle to Boston"). The older fact is marked `SUPERSEDED` with `superseded_by` pointer and validity range closed.

### 2.4 Timeline Event State Machine
- **`POINT`**: Explicit instantaneous event (e.g. `2024-05-12T14:30:00Z`).
- **`INTERVAL`**: Spanned event with `start_time` and `end_time` (e.g. `2024-06-01` to `2024-06-14`).
- **`ORDERED`**: Relative timestamp anchored to another event (e.g. "three days after the conference").
- **`UNKNOWN_TIME`**: Episodic memory where exact time cannot yet be anchored.

## 3. Clock & Temporal Semantics

### 3.1 The Three Time Coordinates
Every memory operation evaluates temporal attributes against three coordinates:
1. $t_{\text{event}}$: Real-world time when the memory event happened.
2. $t_{\text{ingest}}$: System wall-clock time when Almond ingested the record.
3. $t_{\text{ref}}$: Reference perspective time for query, decay, and temporal reasoner evaluation.

### 3.2 Canonical Decay Equation
The single source of truth for dynamic memory freshness is:

$$\Delta t = \max\left(0.0, \frac{t_{\text{ref}} - t_{\text{last\_accessed}}}{86400.0}\right)$$

$$\text{freshness} = \exp\left( -\frac{\lambda}{S} \cdot \Delta t \right)$$

$$\text{Effective Priority } (P_{\text{eff}}) = I_{\text{base}} \times \text{freshness}$$

Where:
- $\lambda$: Tag-based decay rate (defined in `DECAY_CONSTANTS`).
- $S = \frac{\text{access\_count}}{\text{STABILITY\_SCALE}}$: Stability multiplier resisting decay upon repeated recall.
- $I_{\text{base}} \in [1.0, 10.0]$: Base importance score assigned during ingestion.

## 4. Deletion & Index Rebuild Invariants

### 4.1 Cascading Deletion Semantics
When a memory $M_i$ is deleted via `DELETE /v3/memories/{id}`:
1. **SQLite Core**: A database transaction deletes $M_i$ from `memories`.
2. **Relational Links**: SQLite foreign key cascades automatically purge entries in `memory_entities`, `memory_facts`, and `memory_events`.
3. **Orphan Cleanup**: Entities or events with zero remaining memory linkages are flagged as orphaned and evicted or archived.
4. **Derived Vector Cleanup**: Chroma `delete(ids=[M_i])` is synchronously executed.
5. **Audit Record**: An entry is appended to `audit_events` with $M_i$, timestamp, and reason.

### 4.2 Rebuild Semantics (`rebuild_indexes()`)
Derived indexes (Chroma vector embeddings, Timeline chronological trees, Entity alias lookups) can be wiped completely without losing knowledge.
1. The rebuild routine drops the derived Chroma collection.
2. It streams all active/decaying/archived records from the SQLite `memories` table.
3. Embeddings are re-computed and upserted in deterministic batches.
4. Entity graph pointers and timeline intervals are rebuilt in memory and SQLite caches.
5. **Invariant**: An identical SQLite database always yields identical derived index structures.
